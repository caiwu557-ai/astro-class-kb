# Astro 班级知识库阅读桥 0.1.1

用于没有内置浏览器、但支持本地 MCP 的 Agent。已有浏览器工具的 Agent 可以直接使用 `astro-class-kb` Skill。

组成：Chrome/Edge Manifest V3 扩展 + Python 标准库 MCP stdio 桥。只有本机回环通信，不需要云服务器、管理员飞书应用、OpenAI 账号或网站 Cookie。

## 安装与连接

1. 将本包解压到固定目录，保留 `bridge.py`、`extension/` 与其中的 `catalog.json`。
2. 在自己的 Agent 中添加本地 MCP：命令为已经安装的 Python 3.10+，参数为本目录 `bridge.py` 的绝对路径。不需要安装 Python 依赖。本项目测试使用 Python 3.13；MCP 实现及测试版本为 `2025-06-18` stdio，其他协议/客户端需实际验证。

```json
{"mcpServers":{"astro-kb-browser":{"command":"python","args":["/absolute/path/browser-bridge/bridge.py"]}}}
```

Windows 可以填写 Python 的真实 exe 路径，JSON 中的路径使用 `/` 或转义反斜线。不要把示例路径原样当实际路径。
本文件只提供配置例子，没有自动修改任何客户端配置或系统设置。

3. 在 Chrome 的扩展管理页启用开发者模式，选择“加载已解压的扩展程序”，选择 `extension/`。Edge 可使用同类入口。安装需要浏览器权限确认，应由用户明确同意。
4. 打开公开知识库首页：<https://xcnmfu3da215.feishu.cn/wiki/U8U0wMHFVipDpNkXPs6cCbsgn3e>。建议使用专门的阅读标签页；无需登录飞书。
5. 让 Agent 调用 `kb_connection`，取得本次配对码。点击插件图标，填写端口（默认 38473）和配对码，选择“共享当前知识库页并连接”。
6. 保留插件打开的轻量“Astro 阅读桥”标签页。再次调用 `kb_connection` 确认已连接；随后 Agent 可调用读取、导航、滚动、页码、截图和下载工具。

配对码只保存在本次 MCP 进程和扩展会话中，不放进公开文档或分享给别人。重启 MCP 后需重新配对。端口冲突时，用 `--port 其他本机端口` 并在插件填写相同值。

## 使用

- `kb_open` 接受本包目录中的飞书直链，以及已读取知识库页面实际可见的同域 Wiki/文件链接。不能凭空猜节点 ID，也不接受私有 Base 或表单路径。新链接的实际访问仍受读者本人浏览器权限约束。
- `kb_read` 返回当前加载内容，不表示全文件都已读取。利用目录中的页内锚点、滚动和分页定位；发现逐字文本层时下载 PDF 后读取，或使用截图核对。
- `kb_screenshot` 会激活专用阅读页；需要用户点击插件授予该页 `activeTab` 权限。不能截图其他页面。
- `kb_download` 只点击当前页实际可见“下载”按钮。后台文件可能尚未完成，所以再次调用 `kb_download_status`，不要重复点击。只有新下载文件与目录中已知源哈希相同，桥才报告 `verified` 并返回路径。
- 默认在用户 `Downloads` 文件夹核验文件；如果浏览器另设下载目录，在 MCP 参数中加 `--downloads 实际目录`。没有源哈希或没有取得回执时，如实返回 `not_verified`，不能声称保存成功。
- 某些文件查看器的页码输入方式、懒加载或截图授权可能不同；工具会返回具体限制。可退回 Agent 已有的浏览器/文件工具。

## 权限与范围

扩展只声明 `activeTab`、`scripting`、`storage`，主机限当前知识库域名和 `127.0.0.1`。下载通过网页实际按钮触发，不读取浏览器的全局下载历史。
没有 Cookie、历史、书签、调试器、任意网页、原生消息主机或远端代码权限。
HTTP 桥只监听 `127.0.0.1`，校验 Host、扩展 Origin、一次性配对码和目录哈希；不接受普通网页调用。
工具不提供任意 JavaScript、输入表单、修改文档、删除文件、发送消息、读取账户配置或扫描任意本地目录。
插件以知识库目录为种子，后续只沿已读取页面实际可见的同域 Wiki/文件链接导航。不会借用发布者的认证接口导出权限不明确的正文。目录更新后使用同版 Skill/插件；其他站点仍交给常规浏览器工具。
